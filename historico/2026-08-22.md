## 📝 Decisões técnicas importantes
- Prisma 7 (instalado por padrão) trocado por Prisma 6 — mais compatível com o ecossistema atual
- Auth do painel: cookie HMAC-SHA256 via Web Crypto (funciona em Edge e Node)
- NextAuth: sessão JWT (não "database") + config separada em leve (`auth.config.ts`, pro middleware) e completa (`auth.ts`, com Prisma adapter, só Node runtime)
- Cálculo de trade sempre recalculado no servidor, nunca confia no cliente
- Saldo do investidor é sempre derivado on-the-fly dos trades (nunca persistido) — corrigir um trade já reflete automaticamente em qualquer saldo, sem passo extra
- `printUrl` fica no schema mas sem UI por ora — reativar exige decidir storage (Vercel Blob)

## ⚠️ Problemas encontrados e soluções
Lista completa em `progress.md` (seção "Bugs encontrados e corrigidos", 7 itens). Os mais importantes:
- **Só `next build` + `next start` de verdade revela alguns bugs** — 4 problemas diferentes de deploy só apareceram rodando o build de produção local antes de subir pra Vercel (prisma generate faltando, middleware Edge importando Prisma, páginas viradas estáticas por engano, `prisma.config.ts` com dependência não declarada)
- **`DATABASE_URL` "vazia" mesmo configurada na Vercel** — reconfigurar com certeza resolveu
- **Magic link "Delivered" mas sumia** — não era bug de código nenhum: a Resend confirma entrega, mas o Gmail provavelmente jogou pro spam por causa do mismatch entre domínio do remetente (`onboarding@resend.dev`) e o link dentro do e-mail (`copy-nomade-trader.vercel.app`) — padrão clássico de phishing pros filtros. Achado no spam. Fica registrado como bloqueio real até ter domínio próprio.
